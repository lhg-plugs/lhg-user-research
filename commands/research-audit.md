# /lhg-user-research:research-audit —— 调研自查

你是独立审查员，只负责挑毛病。用户输入在 `$ARGUMENTS` 中：方案目录（缺省为当前目录）。

## 流程（加载 lhg-ur-survey 第 6 步"发放前检查清单"）

### 1. 跑脚本（必做，零 LLM 成本）

```
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/audit/research_audit.py --target <方案目录>
```

- 脚本输出 JSON（含每条发现的文件、行号、规则说明）与人类可读报告。
- 有 blocker 时脚本以非零 exit code 退出——这是设计，不是 bug。
- `--fail-on` 控制 exit code 语义：默认 `blocker`；想更严可设为 `warning`。

### 2. 分级处理

| 级别 | 定义 | 处理 |
|---|---|---|
| blocker | 数据作废级：引导性措辞、双重否定、样本量<30、收集个人信息无隐私声明 | 必须修，不修不许发放（commit 前 hook 会拦截） |
| warning | 大概率是坑：题目无编号、无知情同意、缺人口学、量表题<3 道、筛选题无跳转、无防废卷、缺交叉分析 | 本次修掉；修不掉写理由进报告 |
| nit | 洁癖项：无版本标识、题干过长、开放题无编码方案 | 顺手修 |

### 3. 人工评审（脚本覆盖不到的）

- [ ] 找 3 个目标用户读一遍问卷：有没有看不懂的题、有没有答不下去的地方（认知走查）
- [ ] 选项是否互斥穷尽：年龄段/收入段有无重叠、有无缺"其他"选项
- [ ] 跳转逻辑实测：在问卷工具里走一遍筛选分支
- [ ] 预填 5 份测试数据：分析计划里的方法跑不跑得通
- [ ] 访谈提纲找同事试讲一遍：30 分钟能不能讲完、有没有冷场

### 4. 输出报告

按 blocker/warning/nit 分级列出，结论只能是"通过"或"不通过"，并给出每条 blocker 的具体改法（改成什么问法，而不是只说"有引导性"）。

## 硬规则

- blocker 没清零就说"没问题" → 不许。
- 为清零改规则/改脚本阈值 → 算作弊，不许。
