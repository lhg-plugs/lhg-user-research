# lhg-ur-interview：用户访谈

> 目标：挖出问卷挖不到的"为什么"。
> 核心纪律：**问题全开放；每个核心问题配追问；原话记录，不许脑补。**

## 1. 何时使用

- 研究问题是"为什么"（流失原因、购买动机）→ 访谈是主力方法
- 问卷发现了现象，要深挖原因 → 用访谈跟进典型用户
- 新产品/新功能探索期 → 先访谈再定问卷（顺序：定性→定量）
- 用户说"随便聊聊就行"→ 先做第 2 步，不许无提纲访谈

## 2. 输入与输出

**输入**：《研究目标卡》、访谈对象来源（问卷筛选/用户分群/公开招募）。

**输出**：《访谈提纲》（暖场+5~8 核心问题+追问+时长规划）+《招募标准》+《访谈记录模板》。

## 3. 分步方法论

### 第 1 步：定招募标准（包含谁/排除谁）

写清三要素：**画像标准**（如"近 30 天流失的付费用户"）、**排除标准**（如"竞品公司员工、3 个月内访谈过的不再访"）、**人数与配额**（如 10 人，高/低满意各半）。

**招募标准决定访谈质量**。标准模糊 → 招来的人不对 → 问得再好也白搭。招募时多备 20% 候补（有人会放鸽子）。

### 第 2 步：写提纲（五段式）

1. **暖场**（5 分钟，1~2 道）：建立信任，不问敏感问题。"先聊聊您平时是怎么用这类产品的？"——让用户放松、进入回忆状态。
2. **行为回顾**（10 分钟，2 道）："上次您用我们的产品是什么时候？当时发生了什么？"——问具体行为，不问观点。行为是事实，观点是加工过的。
3. **动机深挖**（15 分钟，2~3 道）："当时您为什么这么选？""还有别的考虑吗？"——连续追问"为什么"，直到挖到没法再往下问为止（通常 3~5 个为什么）。
4. **假设验证**（5 分钟，1 道）："我们猜测是因为价格，您觉得呢？"——假设验证放在后面，先让用户自己说，避免污染。
5. **收尾**（5 分钟，1 道）："还有什么想补充的吗？"——黄金问题，经常挖出之前没想到的点。

**问题写法**：全开放式（"怎么""为什么""发生了什么"），不许出现"是不是""好不好"。每个核心问题配 1~2 个追问提示（如"能举个例子吗""当时还有谁在场"）。

### 第 3 步：时长规划（总 30~45 分钟）

每段标注用时。没计时 → 前松后紧 → 核心问题没时间问。**主持人手表上定闹钟**，每段结束前 2 分钟收尾。超时 10 分钟是极限，再长用户开始敷衍。

### 第 4 步：执行规范

- **录音**：必须征得同意（"我可以录音吗？只用于内部分析"），不同意就只记笔记。
- **记录**：原话记录，不许脑补和概括。"用户说价格贵"和用户原话"我觉得 199 有点肉疼，隔壁才 149"是两回事——原话才有分析价值。
- **主持人纪律**：多听少说，不打断，不评价（"这个想法很好"也是引导），不辩解（用户批评产品时不许解释）。
- **观察记录**：记下用户的表情、停顿、犹豫——"说到价格时笑了"本身就是数据。

### 第 5 步：访谈记录模板

```markdown
## 访谈记录（编号 U01，日期__）
- 用户画像：__
- 核心原话（逐条）：__
- 观察记录（表情/停顿/犹豫）：__
- 初步洞察：__
- 待验证的假设：__
```

当天整理，不许拖过 24 小时——记忆会美化，细节会丢失。

## 4. 反模式

- **无提纲访谈**："随便聊聊"——聊完发现关键问题没问。对策：五段式提纲是硬门。
- **封闭式问题**："你觉得我们的产品好吗？"——只能得到"是/还行"。对策：全开放式，"好"在哪里、"不好"具体是哪次。
- **不追问**：用户说"因为贵"，就记下来了。对策：每个核心问题配追问，"贵"是指绝对价格贵还是相对竞品贵？贵多少就接受了？
- **先入为主**：把假设放在前面问，污染用户。对策：假设验证放第 4 段，先让用户自己说。
- **脑补记录**：把原话概括成自己的话。对策：原话记录，分析时再概括。
- **为用户辩解**：用户批评产品，主持人开始解释。对策：主持人只提问不辩护，解释留到复盘会。
- **信息不饱和就停**：访谈 5 个人就出报告。对策：连续 2~3 场无新观点才停，一般 8~15 人。

### 追问话术库（主持人随身带）

| 场景 | 追问话术 |
|---|---|
| 用户只说结论（"因为贵"） | "能具体说说吗？当时是什么情况？" |
| 用户泛泛而谈 | "能举个最近一次的例子吗？" |
| 挖动机 | "当时您还考虑过别的吗？最后为什么选了这个？" |
| 用户停顿/犹豫 | （沉默 3 秒）"嗯，您刚才停了一下，是想到了什么吗？" |
| 用户跑题 | "这个很有意思，我们记下来；回到刚才那个问题……" |
| 用户问"你觉得呢" | "我更想听听您的看法，您是怎么想的？" |

**沉默是最好的追问**。用户说完停顿时，别急着接话，沉默 3 秒——70% 的情况下用户会自己往下说出更深的东西。新手主持人最缺的就是这 3 秒。

### 访谈后 24 小时整理清单

- [ ] 录音转文字（当天转，不许拖）
- [ ] 按记录模板填好：原话/观察/初步洞察
- [ ] 标出 3 句"金句"（最有代表性的原话）
- [ ] 写下 1 个新假设（这次访谈冒出来的、之前没想到的）
- [ ] 更新招募：如果发现某类用户观点高度一致，下一场换一类用户（保证多样性）

**访谈是滚雪球**：每场结束都问自己"这场推翻了/修正了之前的哪个假设"，带着新问题进下一场。10 场下来，你对用户的理解会深得吓人。

### 线上访谈特别规范（视频/电话访谈）

- **开摄像头**：看不到表情，损失一半信息。用户不开摄像头 → 至少电话，保证声音质量。
- **网络测试**：提前 10 分钟进会议室测试音视频，准备电话备用方案。
- **屏幕共享**：让用户共享屏幕操作产品，"您平时怎么找到这个功能的"——看他真实的操作路径，比听他说管用 10 倍。
- **防分心**：开场就说"接下来 30 分钟需要您专注"，中途用户看手机 → 温和拉回："刚才那个问题您还没说完"。
- **录音备份**：线上录制+本地录音双备份，云端录制可能失败。

### 访谈对象激励

访谈 30~45 分钟，给用户合理的激励（红包/优惠券/小礼品），标准是"让用户觉得时间没白花"。**激励在访谈结束后给**，提前给会变成"拿钱办事"的心态。招募时说清"有答谢"，不说具体金额，避免为钱来的人。

### 难约的用户怎么约

高管、专家型用户难约，三个办法：熟人介绍（成功率最高）、错峰约（早 8 点前/晚 9 点后，他们反而有空）、缩短时长（"只要 15 分钟，3 个问题"——先约上再说，聊得好自然延长时间）。

> 主持人最重要的素质不是口才，是好奇心。对用户正在说的话真好奇，
> 追问自然就跟上了；不好奇，话术库背得再熟也像审问。

### 访谈禁忌清单（贴在主持人手边）

- [ ] 不评价用户（"这个想法很好"也是引导）
- [ ] 不辩解（用户批评产品时不许解释）
- [ ] 不打断（用户停顿是在思考，不是说完了）
- [ ] 不预设（"你是不是觉得贵"→ 改成"你觉得价格怎么样"）
- [ ] 不超时（45 分钟是极限，超时用户开始敷衍）

**违反任何一条，当场在心里记一笔，访谈后复盘**。主持人和问卷一样，需要迭代——每场结束问自己"这场我打断了几次"，次数降下来了，水平就上来了。

## 5. 自检与反馈

**质检门**：

- [ ] 招募标准三要素齐全（画像/排除/人数配额）
- [ ] 提纲五段式完整，5~8 个核心问题
- [ ] 问题全开放式，无"是不是""好不好"
- [ ] 每个核心问题有 1~2 个追问提示
- [ ] 有时长规划（每段几分钟，总 30~45 分钟）
- [ ] 有录音知情说明
- [ ] 访谈记录模板已准备（原话/观察/洞察分区）

**标准冒烟用例**：输入"流失用户深访"，应输出五段式提纲 + 招募标准 + 记录模板，且问题全为开放式；出现封闭式问题应明确标出并重写。

**反馈**：发现 bug 或有改进建议，以 `[QC] <一句话问题>` 为标题提交到 https://github.com/lhg-plugs/lhg-user-research/issues，正文写清"复现步骤 → 实际表现 → 期望表现"。
