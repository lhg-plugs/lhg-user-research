# lhg-ur-insight：数据分析与洞察报告

> 目标：把数据变成"能指导决策"的洞察，而不是"数据的复述"。
> 核心纪律：**每条洞察标注证据强度；先说局限再说结论；洞察必须对应行动建议。**

## 1. 何时使用

- 问卷回收完成，要分析 → 全流程
- 访谈结束，要整理 → 第 4 步（定性编码）
- 报告写完要自查 → 第 5 步清单
- 结论没人用 → 回看第 6 步"洞察三要素"

## 2. 输入与输出

**输入**：回收的问卷数据（CSV/问卷平台导出）、访谈记录、分析计划（来自 lhg-ur-survey 第 1 步）。

**输出**：《洞察报告》：核心发现（3~5 条）/ 数据支撑 / 局限说明 / 行动建议。

## 3. 分步方法论

### 第 1 步：数据清洗（先清洗再分析）

1. 剔废卷：按防废卷规则（注意力检测不通过、作答时长过短、前后矛盾）剔除，**记录废卷率**——废卷率超过 20% 说明问卷或渠道有问题。
2. 查缺失：核心题缺失率高的题，结论要降级（证据不足）。
3. 查分布：样本结构 vs 配额，偏了要加权或注明局限。

### 第 2 步：描述统计（先看全貌）

每个维度先看分布：均值/中位数、Top2 Box（量表 4~5 分占比）、排序题的平均排名。**先看分布再看差异**——总体满意度 3.2 分和"一半人打 5 分一半人打 1 分"是完全不同的故事。

### 第 3 步：交叉分析（挖差异）

按人口学维度交叉：性别×满意度、年龄×推荐意愿、城市线级×价格敏感度。**差异才是洞察的矿**：总体平均 3.5 分没意义，"25 岁以下 4.2 分、40 岁以上 2.8 分"才有意义。每个显著差异追问一句"为什么"——能用访谈原话解释的，证据强度升一级。

### 第 4 步：开放题/访谈编码（三步走）

1. **开放编码**：逐条读，把原话贴标签（如"价格贵""客服慢""功能找不到"）。
2. **归类**：标签聚成 3~7 个主题，主题名用用户的原话风格（如"199 有点肉疼"）。
3. **计数**：每个主题有多少人提到——定性也要有"量"的感觉，但不许做统计推断（"30% 用户提到"可以，"30% 用户认为"不行，访谈样本不代表总体）。

### 第 5 步：写洞察报告（模板）

```markdown
## 用户调研洞察报告（主题+日期）
### 核心发现（3~5 条，每条按三要素写）
- 发现：__
- 数据支撑：__（问卷数据/访谈原话编号）
- 证据强度：强/中/弱
### 局限说明
- 样本局限：__（如"样本偏年轻，40+用户结论慎用"）
- 方法局限：__（如"开放题回收率低，原因类结论以访谈为准"）
### 行动建议（每条对应决策用途）
- 建议__ 预期效果__ 负责人__
```

**洞察三要素**：发现（是什么）+ 证据（怎么证明的）+ 行动（所以呢）。缺"所以呢"的发现是正确的废话，删掉。

### 第 6 步：证据强度分级

| 强度 | 标准 | 能怎么用 |
|---|---|---|
| 强 | 问卷显著差异 + 访谈原话印证 | 直接指导决策 |
| 中 | 只有问卷数据或只有访谈 | 可做决策参考，需小规模验证 |
| 弱 | 个别访谈提到、问卷无印证 | 记为假设，下一轮验证 |

**报告里不许出现"用户觉得"这种没主语的话**——是"多少用户"、"哪些用户"、"在什么场景下"，说清楚。

## 4. 反模式

- **复述数据**："满意度 3.5 分"——这叫数据，不叫洞察。对策：每条发现必须回答"所以呢"。
- **平均数陷阱**：只看总体平均，不看分布和差异。对策：第 2 步看分布，第 3 步挖交叉。
- **定性当定量**："访谈了 5 个人，3 个说贵，所以 60% 用户觉得贵"——错。对策：定性只谈"有没有这个现象"，不谈比例。
- **报喜不报忧**：只写支持预设的结论。对策：第 5 步局限说明是强制章节，反例必须写进去。
- **洞察无行动**：报告结尾没有"所以我们要做什么"。对策：每条洞察配行动建议，对应目标卡的决策用途。
- **证据不分级**：所有结论一个口气。对策：第 6 步分级，弱证据的结论明确标出来。

### 洞察报告示例（一条完整的）

```markdown
- 发现：40 岁以上用户对"操作复杂"的抱怨是 25 岁以下的 3 倍，是低满意的主因。
- 数据支撑：问卷 Q9（操作便捷度）40+组均分 2.8 vs 25岁以下 4.2（p<0.05）；
  访谈 U03/U07 原话："我找了半天没找到退款入口"。
- 证据强度：强（问卷显著差异 + 访谈印证）。
- 行动建议：退款入口在"我的订单"页首屏露出，预计提升 40+用户满意度 0.5 分。
  负责人：产品小李；上线后 2 周复测 Q9。
```

**好洞察的四个特征**：具体（40+用户，不是"部分用户"）、有对比（3 倍）、有原话（有血有肉）、有行动（谁来做、什么时候验证）。

### 报告呈现技巧

- **电梯汇报版**（1 页）：3 条核心发现 + 1 条最优先的行动建议。老板只看这一页。
- **完整版**（10~15 页）：发现 + 数据 + 局限 + 附录（问卷全文、样本结构）。
- **汇报顺序**：先讲行动建议，再讲数据支撑——决策者关心"做什么"，研究者才关心"怎么算的"。
- **原话是最好的幻灯片**：每页放一句用户原话，比 10 张图表都有说服力。

### 复用：洞察资产库（别让报告沉底）

报告交付不是终点。建一个《洞察资产库》文档，每条洞察一条记录：

```markdown
- 洞察：40+用户觉得操作复杂（2026-10 调研，证据强度：强）
- 状态：已行动（退款入口已露出，待 2 周后复测）/ 待行动 / 已验证 / 已证伪
- 关联决策：产品路线图 v2.3
```

**每季度翻一次资产库**：哪些洞察被验证了、哪些被证伪了、哪些还没行动。调研最大的浪费不是做得不好，是做完了没人记得。资产库就是对抗遗忘的武器。

### 给决策者的一页纸写法

```markdown
## 调研结论一页纸（给老板看的）
- 一句话结论：__
- 3 条核心发现（每条一句话 + 一个数字）：__
- 最优先的行动建议：__（谁来做、什么时候验证）
- 最大的局限：一句话__
```

**先给一页纸，再给完整版**。老板有时间自然会翻完整版，没时间一页纸也够决策。顺序反了（先给 30 页报告），大概率没人看完。

## 5. 自检与反馈

**质检门**：

- [ ] 废卷已剔除，废卷率已记录（>20% 要说明原因）
- [ ] 描述统计先看分布，不只看平均数
- [ ] 交叉分析 ≥1 个维度，差异有"为什么"的解释
- [ ] 开放题/访谈已编码，主题 3~7 个
- [ ] 核心发现 3~5 条，每条有三要素（发现/证据/行动）
- [ ] 证据强度已分级，无"用户觉得"式模糊表述
- [ ] 局限说明已写，反例已记录

**标准冒烟用例**：输入一份问卷 CSV（带人口学字段），应输出清洗说明 + 描述统计 + 至少 1 个交叉分析 + 带证据强度的洞察报告，而不是只有平均数表格。

**反馈**：发现 bug 或有改进建议，以 `[QC] <一句话问题>` 为标题提交到 https://github.com/lhg-plugs/lhg-user-research/issues，正文写清"复现步骤 → 实际表现 → 期望表现"。
